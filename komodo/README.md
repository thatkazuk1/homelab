# komodo/

**Status:** Komodo is live and is the fleet's GitOps orchestrator (Komodo Core on
`komodo-prod-01`, Periphery agents across the standard fleet). This is not a stale
placeholder — see `CLAUDE.md` and `handbook/docs/operations/deploy-triggers.md` for the
current deploy pipeline.

## `resources/default.toml`

Komodo's own resource definitions (servers, stacks, procedures, the repo, and the sync
resource below) — version-controlled config-as-code, reconciled by a `ResourceSync` resource
named `homelab-resources` (Git Repository Mode, `managed: true`, `resource_path =
["komodo/resources/default.toml"]`). See **ADR-0017** for the full decision, the
self-referential-update footgun, and the managed-mode deletion-behavior verification.

This file is generated by Komodo's own `ExportAllResourcesToToml` API, not hand-authored.
**Any change to a Komodo resource made in the UI must be re-exported and committed here**
before the next push-triggered sync runs, or the sync will try to reconcile against a stale
file — this is especially important for `deploy-all-changed` and for `homelab-resources`
itself, since editing either of those live and then letting a stale-TOML sync run against
them is the exact failure mode ADR-0017 documents (`procedure sync loop exited after max
iterations`, or a config field silently reverting).

To re-export: `ExportAllResourcesToToml` via the Komodo API (see `scripts/secrets.enc.env`
for the credential pattern used by `scripts/generate-fleet-inventory.py`), grep the result
for secret-shaped values before committing (never assume it's clean), then commit.

Deploys are **not** driven by this sync. `deploy: true` is deliberately unset — the ADR-0015
Procedure (`deploy-all-changed`) still owns deploys, triggered by the same single repo-level
Forgejo webhook. This sync's `RunSync` runs as that Procedure's *first* stage, ahead of the
existing `Batch Deploy Stack If Changed` stage, so config reconciles before any deploy runs —
not via a second webhook. Komodo's `deploy: true`-on-sync path remains documented-unreliable
upstream (`moghtech/komodo#1120`, `#1381`) and isn't used here for that reason, unchanged
from the original Sprint 3p finding.

Every Stack's own compose definition still lives under `stacks/<name>/` (ADR-0009), not
here — this directory covers Komodo's resource metadata (which servers/stacks/procedures
exist and how they're configured), not stack contents.
